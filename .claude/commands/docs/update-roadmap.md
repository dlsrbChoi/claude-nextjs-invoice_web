# Claude 명령어: 로드맵 업데이트

`docs/ROADMAP.md`에서 완료된 Task와 Phase의 상태를 대화형으로 확인하고 자동으로 갱신합니다.

> 💡 이 커맨드는 `roadmap-updater` 에이전트를 호출하여 실행됩니다. 에이전트가 완료 근거를 수집하고 사용자 확인을 받은 후 문서를 갱신합니다.

## 사용법

```
/docs:update-roadmap            # 완료 후보를 자동 탐지해 대화형으로 확인
/docs:update-roadmap 004        # Task 004 완료 여부만 확인
/docs:update-roadmap 005 006    # 여러 Task를 한 번에 확인
```

## 프로세스

### 1단계 — 현재 로드맵 파악

`docs/ROADMAP.md`를 읽어 다음을 추출합니다:

- 현재 완료된 Phase와 Task의 상태 (`✅` 마크 유무)
- 미완료(`✅` 없는) Task 목록
- 각 Task의 하위 구현 항목 및 테스트 체크리스트 상태

Task 번호가 주어졌으면 해당 Task만, 주어지지 않으면 미완료 Task 전체를 대상으로 진행합니다.

### 2단계 — 완료 근거 수집

각 대상 Task에 대해 완료 여부를 판단하기 위한 근거를 수집합니다(**코드 수정이나 테스트 실행은 하지 않으며 읽기만 수행**):

- **관련 파일 존재 여부**: Task 하위 구현 항목에 언급된 파일(`src/components/...`, `src/lib/...` 등)이 실제로 존재하는지 확인
- **git 커밋/변경 이력**: `git log`와 `git diff` 명령으로 해당 파일의 최근 변경 이력을 확인
- **코드 패턴 분석**: 파일 내용을 읽어 구현 항목이 설명하는 기능/컴포넌트/함수가 실제로 구현되어 있는지 확인 (정적 텍스트 분석만)
- **하위 항목 체크박스 상태**: 문서 내 체크박스가 이미 부분적으로 체크된 경우 그 현황 반영

### 3단계 — 사용자 확인

수집한 근거를 바탕으로 완료로 보이는 항목들을 제시하고, **사용자에게 어떤 항목을 체크할지 확인받습니다**.

예시:

```
✅ 가능한 완료 항목:

Task 004: 견적서 화면 UI 완성 (더미 데이터)
  근거:
  - src/components/invoice/invoice-detail.tsx 존재 (최근 수정: 2h 전)
  - src/components/invoice/invoice-lookup.tsx 존재
  - src/lib/mock-data.ts 존재 (3개 더미 데이터 포함)
  - 모든 하위 구현 항목에 ✅ 표시됨
  - 모든 테스트 체크리스트 항목에 ✅ 표시됨

⚠️  보류 항목:

Task 005: Notion 연동 기반 구축 및 URL 규칙 확립
  근거:
  - (우선순위) 표시가 있으므로 아직 시작 전 상태
  - src/lib/notion.ts 존재하지만 fetch 기반 stub 상태

위 항목들을 모두 체크할까요? 또는 특정 항목만 선택하세요.
(예: "004만 체크", "004 005 모두", "보류")
```

**중요**: 이 커맨드는 완료 여부를 **자동 판단하지 않습니다**. 항상 사용자 확인을 거쳐야 합니다.

### 4단계 — 문서 갱신

사용자 확인이 완료되면 `Edit` 도구로 ROADMAP.md를 다음과 같이 갱신합니다:

#### 하위 구현 항목 체크

```
  - 설명 → - ✅ 설명
```

#### Task 완료 표시

해당 Task의 **모든 하위 항목 + 테스트 체크리스트가 전부 `✅`가 되면** Task 제목을 갱신합니다:

```
- **Task XXX: ...**  →  - **Task XXX: ...** ✅ - 완료
```

기존에 `(우선순위)` 표기가 붙어 있었다면 제거합니다.

#### Phase 완료 표시

해당 Phase의 **모든 Task가 완료되면** Phase 제목을 갱신합니다:

```
### Phase N: ...  →  ### Phase N: ... ✅ (완료)
```

기존에 `(진행 중)` 표기가 있었다면 제거합니다.

#### 다음 우선순위 작업 표시

새로 완료된 Phase의 다음 Phase가 존재하고, 그 첫 Task가 대기 상태라면:

```
- **Task M: ...**  →  - **Task M: ...** (우선순위)
```

이렇게 다음 작업을 명시합니다 (development-planner 에이전트 원칙 준수).

#### MVP 성공 기준 표 갱신

"MVP 성공 기준" 표의 "상태" 컬럼에서, 방금 완료된 Task가 유일하게 연결된 기준이 있다면:

```
| # | 기준 | 관련 Task | 상태 |
| 2 | 고유 URL로 접근 시 견적서가 웹에서 정확하게 표시됨 | Task 004, 006 | ⬜ |
↓
| 2 | 고유 URL로 접근 시 견적서가 웹에서 정확하게 표시됨 | Task 004, 006 | ✅ |
```

(Task 004만 완료된 경우 ⬜ 유지, Task 004+006 모두 완료 시에만 ✅)

### 5단계 — 결과 요약

갱신 완료 후 다음과 같이 요약합니다:

```
✅ 완료 처리된 항목:
- Task 004 (13개 하위 항목 + 5개 테스트 항목)
- Phase 2 전체

⏸️  보류된 항목:
- Task 005 (우선순위 표시 유지)

💾 docs/ROADMAP.md가 갱신되었습니다.
다음 단계: git add + git commit 을 수행하려면 `/git:commit`을 실행하세요.
```

**git 커밋은 이 커맨드에서 수행하지 않습니다.** 사용자가 필요시 `/git:commit`으로 별도 진행해주세요.

## 상태 표기 규칙

이 커맨드가 준수하는 ROADMAP.md의 상태 표기 규칙:

| 대상               | 미완료 상태            | 완료 상태                        | 특수 상태                         |
| ------------------ | ---------------------- | -------------------------------- | --------------------------------- |
| **Phase**          | `### Phase N: 이름`    | `### Phase N: 이름 ✅ (완료)`    | `### Phase N: 이름 (진행 중)`     |
| **Task**           | `- **Task NNN: 이름**` | `- **Task NNN: 이름** ✅ - 완료` | `- **Task NNN: 이름** (우선순위)` |
| **하위 구현 항목** | `  - 설명`             | `  - ✅ 설명`                    | —                                 |
| **테스트 항목**    | `  - 시나리오`         | `  - ✅ 시나리오`                | —                                 |
| **MVP 성공 기준**  | `⬜`                   | `✅`                             | —                                 |

## 주의사항

1. **자동 판단 없음**: 이 커맨드는 완료 여부를 추정만 할 뿐, 반드시 **사용자 확인을 거쳐야** 체크 표시를 반영합니다.

2. **읽기 전용 상태 분석**: 파일 내용과 git 이력을 읽기만 수행하며, 코드를 수정하거나 테스트를 실행하지 않습니다.

3. **shrimp-task-manager 미포함**: `shrimp_data/tasks.json`(shrimp-task-manager MCP 상태)은 건드리지 않습니다. 이 커맨드는 `docs/ROADMAP.md` 단일 문서만 대상으로 합니다.

4. **구조 변경 금지**: 문서의 전체 구조(섹션 순서, 표, 구분선 등)를 변경하지 않고, **상태 표기(`✅`, `(완료)`, `(우선순위)` 등)만 갱신**합니다.

5. **git 커밋 미포함**: 파일 수정까지만 수행합니다. 커밋이 필요하면 `/git:commit` 또는 `/commit`을 별도로 실행해주세요.

## 사용 예시

### 모든 미완료 Task 후보 확인

```
/docs:update-roadmap
```

모든 Task를 스캔하여 완료 후보를 제시합니다.

### 특정 Task만 확인

```
/docs:update-roadmap 005
```

Task 005의 완료 여부만 확인합니다.

### 여러 Task 일괄 확인

```
/docs:update-roadmap 005 006 007
```

Task 005, 006, 007을 한 번에 확인합니다.

## 문제 해결

### "Task NNN이 이미 완료된 상태입니다"

이미 `✅ - 완료` 표기가 있는 Task는 제외됩니다. 상태를 다시 확인하고 싶으면 문서에서 `✅ - 완료` 표기를 일시 제거한 후 다시 실행해주세요.

### "근거가 부족합니다" 메시지

Task의 하위 구현 항목이 설명하는 파일이 코드에 실제로 없거나, 최근 변경 이력이 없을 수 있습니다. 파일 경로를 확인하고 필요시 수동으로 체크해주세요.

### 실수로 완료 처리한 경우

문서를 직접 열어 해당 항목의 `✅` 표기를 제거한 후, `/docs:update-roadmap` 다시 실행하세요.
