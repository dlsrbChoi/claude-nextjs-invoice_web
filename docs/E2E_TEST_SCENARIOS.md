# E2E 테스트 시나리오

## 개요

이 문서는 Playwright MCP를 사용한 엔드-투-엔드 테스트 시나리오를 정의합니다.

## 테스트 환경 구성

```bash
# 로컬 개발 서버 시작
npm run dev

# 테스트 실행
# Playwright MCP 를 사용하여 테스트 수행
```

## 테스트 시나리오

### 시나리오 1: 홈페이지 접근 및 네비게이션

**목표**: 홈페이지에서 견적서 조회 기능이 정상 작동

**단계**:

1. 루트 URL (http://localhost:3000) 접근
2. "견적서 관리 시스템" 제목 표시 확인
3. "견적서 조회" 입력 필드 확인
4. 더미 데이터로 테스트 (예: 유효한 Notion 페이지 ID)
5. 견적서 상세 페이지로 네비게이션 확인

**예상 결과**:

- ✅ 홈페이지 렌더링 성공
- ✅ 입력 필드에 접근 가능
- ✅ 견적서 상세 페이지 로드

### 시나리오 2: 로그인 플로우

**목표**: 관리자 인증 시스템이 정상 작동

**단계**:

1. /login 페이지 접근
2. 비밀번호 입력 필드 확인
3. 잘못된 비밀번호 입력 및 에러 메시지 확인
4. 올바른 비밀번호 입력
5. /admin 페이지로 자동 리다이렉트 확인
6. 세션 쿠키 설정 확인

**예상 결과**:

- ✅ 로그인 페이지 렌더링
- ✅ 잘못된 비밀번호 시 에러 토스트 표시
- ✅ 성공 시 /admin으로 리다이렉트
- ✅ admin_session 쿠키 설정 확인

### 시나리오 3: 관리자 인증 보호

**목표**: 인증 없이 /admin 접근 시 로그인 페이지로 리다이렉트

**단계**:

1. 세션 쿠키 삭제 (또는 시크릿 모드에서 시작)
2. /admin 페이지 직접 접근
3. /login 페이지로 리다이렉트 확인
4. URL의 from 파라미터에 원래 경로 포함 확인

**예상 결과**:

- ✅ /admin 접근 시 자동으로 /login으로 리다이렉트
- ✅ from=/admin 파라미터 포함
- ✅ 로그인 후 /admin으로 돌아가기 가능 (선택사항)

### 시나리오 4: 관리자 목록 조회

**목표**: 인증 후 견적서 목록 표시

**단계**:

1. 로그인 (시나리오 2 참고)
2. /admin 페이지 접근
3. 견적서 목록 테이블 렌더링 확인
4. 테이블의 컬럼 확인: 견적서, 고객명, 발급일, 금액, 상태, 액션
5. "링크 복사" 버튼 작동 확인
6. 견적서 항목 클릭 후 상세 페이지로 이동 확인

**예상 결과**:

- ✅ /admin 페이지 로드 (NOTION_DATABASE_ID 설정 필수)
- ✅ 견적서 목록 테이블 렌더링
- ✅ 각 항목의 링크 복사 기능 작동
- ✅ 상세 페이지 네비게이션 정상

### 시나리오 5: 견적서 상세 조회

**목표**: 견적서 상세 정보가 올바르게 표시

**단계**:

1. 견적서 상세 페이지 (예: /invoice/[notionPageId]) 접근
2. 제목, 송장번호, 발급일 등 기본 정보 표시 확인
3. 청구 대상 정보 표시 확인
4. 항목 목록 테이블 또는 카드 표시 확인
5. 총액 표시 확인
6. "링크 복사" 버튼 작동 확인
7. "PDF 다운로드" 버튼 클릭 시 인쇄 대화 열림 확인

**예상 결과**:

- ✅ 상세 정보 올바르게 표시
- ✅ 항목 목록 표시 (테이블 또는 카드)
- ✅ 링크 복사 기능 작동
- ✅ PDF 다운로드 기능 작동

### 시나리오 6: 로그아웃

**목표**: 로그아웃 기능이 정상 작동하고 세션 종료

**단계**:

1. /admin 페이지에서 헤더의 메뉴 아이콘 클릭
2. 로그아웃 메뉴 항목 확인
3. 로그아웃 클릭
4. 홈페이지 (/로 리다이렉트 확인
5. /admin 재접근 시 로그인 페이지로 리다이렉트 확인
6. admin_session 쿠키 삭제 확인

**예상 결과**:

- ✅ 로그아웃 메뉴 항목 표시
- ✅ 로그아웃 후 홈페이지로 리다이렉트
- ✅ 세션 쿠키 삭제
- ✅ /admin 재접근 시 인증 필요

### 시나리오 7: 반응형 디자인 검증

**목표**: 모바일 및 데스크톱 환경에서 정상 작동

**단계**:

1. 데스크톱 브라우저 (1920x1080) 에서 /admin 접근
2. 테이블 레이아웃 확인
3. 모바일 브라우저 (375x667, iPhone SE) 로 리사이즈
4. 카드 레이아웃 확인
5. 각 요소의 상호작용 정상 확인
6. 터치 이벤트 시뮬레이션 (버튼 클릭, 스크롤 등)

**예상 결과**:

- ✅ 데스크톱: 테이블 뷰 정상 표시
- ✅ 모바일: 카드 뷰 정상 표시
- ✅ 모든 버튼 접근 가능 및 작동
- ✅ 스크롤 가능

### 시나리오 8: 다크 모드 검증

**목표**: 라이트/다크 모드 전환이 정상 작동

**단계**:

1. 헤더의 테마 토글 아이콘 클릭
2. 다크 모드로 전환 확인 (배경, 텍스트 색상)
3. 페이지 새로고침 후 다크 모드 유지 확인
4. 라이트 모드로 다시 전환
5. 색상 명도 기준 충족 확인 (WCAG AA)

**예상 결과**:

- ✅ 테마 토글 작동
- ✅ 색상 변경 즉시 반영
- ✅ localStorage에 테마 설정 저장
- ✅ 모든 텍스트 명도 기준 충족

### 시나리오 9: 에러 처리

**목표**: 에러 상황에서 사용자 친화적 메시지 표시

**단계**:

1. 로그인 시 ADMIN_PASSWORD 환경 변수 미설정 상태 시뮬레이션
2. 서버 오류 메시지 확인
3. 관리자 페이지에서 NOTION_DATABASE_ID 미설정 상태 시뮬레이션
4. 설정 오류 메시지 확인
5. 네트워크 오류 시뮬레이션 (DevTools에서 온라인 상태 토글)
6. 로그인 시 네트워크 오류 토스트 확인

**예상 결과**:

- ✅ 설정 오류 시 명확한 메시지 표시
- ✅ 네트워크 오류 시 토스트 알림
- ✅ 에러 페이지 렌더링 정상

## 성능 테스트

### 로드 타임 기준

- **홈페이지**: < 2초
- **관리자 페이지**: < 3초 (Notion API 포함)
- **상세 페이지**: < 2초

### 측정 방법

```javascript
// DevTools Performance 탭에서 측정
1. 페이지 로드 전 Performance 탭 열기
2. 새로고침 버튼 클릭
3. 로드 완료 대기
4. 결과 분석
   - FCP (First Contentful Paint)
   - LCP (Largest Contentful Paint)
   - CLS (Cumulative Layout Shift)
```

## 접근성 테스트

### 키보드 네비게이션

- Tab 키로 모든 인터랙티브 요소 접근 가능
- Enter/Space 키로 버튼 활성화
- Escape 키로 드롭다운 메뉴 닫기

### 스크린 리더

- 모든 이미지에 alt 텍스트 제공
- 버튼에 의미있는 텍스트 또는 aria-label 제공
- 폼 필드에 label 연결
- 테이블의 caption 제공

## 테스트 환경 요구사항

- **브라우저**: Chrome/Chromium (최신 버전)
- **Node.js**: 18.x 이상
- **Playwright**: MCP 호환 버전
- **환경 변수**: .env.local에 필수 변수 설정
  - NOTION_API_KEY
  - NOTION_DATABASE_ID
  - ADMIN_PASSWORD
  - NEXT_PUBLIC_APP_URL=http://localhost:3000
