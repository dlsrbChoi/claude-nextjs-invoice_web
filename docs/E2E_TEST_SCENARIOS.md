# E2E 테스트 시나리오 - v3.0 통합 검증

## 개요

이 문서는 Playwright MCP를 사용한 엔드-투-엔드 테스트 시나리오를 정의합니다.
v3.0에서는 관리자 전체 플로우(대시보드, 페이지네이션, 링크 복사, 이메일 발송, 신고 관리)와
보안 경계, 회귀 테스트(v1.0 공개 조회, v2.0 호환성)를 검증합니다.

## 테스트 환경 구성

```bash
# 로컬 개발 서버 시작
npm run dev

# 필수 환경 변수 (.env.local 참고)
NOTION_API_KEY=your_notion_api_key_here
NOTION_DATABASE_ID=your_notion_database_id_here
NOTION_REPORTS_DATABASE_ID=your_notion_reports_database_id_here  # v3.0 신규
ADMIN_SESSION_SECRET=your_session_secret_32bytes_or_longer      # v3.0 신규
ADMIN_PASSWORD=your_admin_password                              # v3.0 신규
EMAIL_API_KEY=your_resend_api_key_here (optional)              # v3.0 선택
EMAIL_FROM_ADDRESS=noreply@example.com (optional)              # v3.0 선택
```

## 테스트 시나리오

### 시나리오 1: 홈페이지 접근 및 네비게이션

**목표**: 홈페이지에서 견적서 조회 기능이 정상 작동

**단계**:

1. 루트 URL (http://localhost:3000) 접근
2. "견적서 관리 시스템" 제목 표시 확인
3. "견적서 조회" 입력 필드 확인
4. 더미 데이터로 테스트 (예: 유효한 Notion 페이지 ID)
5. 견적서 상세 페이지로 네비게이션 확인

**예상 결과**:

- ✅ 홈페이지 렌더링 성공
- ✅ 입력 필드에 접근 가능
- ✅ 견적서 상세 페이지 로드

### 시나리오 2: 로그인 플로우

**목표**: 관리자 인증 시스템이 정상 작동

**단계**:

1. /login 페이지 접근
2. 비밀번호 입력 필드 확인
3. 잘못된 비밀번호 입력 및 에러 메시지 확인
4. 올바른 비밀번호 입력
5. /admin 페이지로 자동 리다이렉트 확인
6. 세션 쿠키 설정 확인

**예상 결과**:

- ✅ 로그인 페이지 렌더링
- ✅ 잘못된 비밀번호 시 에러 토스트 표시
- ✅ 성공 시 /admin으로 리다이렉트
- ✅ admin_session 쿠키 설정 확인

### 시나리오 3: 관리자 인증 보호

**목표**: 인증 없이 /admin 접근 시 로그인 페이지로 리다이렉트

**단계**:

1. 세션 쿠키 삭제 (또는 시크릿 모드에서 시작)
2. /admin 페이지 직접 접근
3. /login 페이지로 리다이렉트 확인
4. URL의 from 파라미터에 원래 경로 포함 확인

**예상 결과**:

- ✅ /admin 접근 시 자동으로 /login으로 리다이렉트
- ✅ from=/admin 파라미터 포함
- ✅ 로그인 후 /admin으로 돌아가기 가능 (선택사항)

## 보안 경계 검증 (v3.0 신규)

### 시나리오 10: 위조 쿠키 차단 (회귀 방지)

**목표**: HMAC 서명 검증으로 위조된 세션 토큰 차단

**단계**:

1. 브라우저 DevTools 콘솔에서 위조 쿠키 주입:
   ```javascript
   document.cookie = 'admin_session=fake; path=/; max-age=3600';
   ```
2. `/admin` 접근
3. `/admin/login`으로 리다이렉트 확인
4. 정상 로그인 후 발급된 쿠키를 일부 변조:
   ```javascript
   const cookie = document.cookie;
   const modified = cookie.slice(0, -5) + '00000'; // 서명 마지막 5글자 변조
   document.cookie = `admin_session=${modified}; path=/; max-age=3600`;
   ```
5. 페이지 새로고침
6. `/admin/login`으로 리다이렉트 확인

**예상 결과**:

- ✅ 임의의 값으로는 `/admin` 접근 불가
- ✅ 서명 변조 감지 및 세션 무효화
- ✅ 매번 로그인 페이지로 차단
- ✅ 오류 로그 기록

### 시나리오 11: 미인증 API 호출 차단

**목표**: 인증 없이 관리자 API 호출 차단

**단계**:

1. 쿠키 전부 삭제 (또는 시크릿 모드)
2. curl 또는 Postman으로 미인증 API 호출:
   ```bash
   # 신고 상태 변경
   curl -X PATCH http://localhost:3000/api/admin/reports/[reportId] \
     -H "Content-Type: application/json" \
     -d '{"status": "resolved"}'

   # 이메일 발송
   curl -X POST http://localhost:3000/api/admin/share-email \
     -H "Content-Type: application/json" \
     -d '{"notionPageId": "...", "toEmail": "...", "subject": "..."}'
   ```
3. 401 Unauthorized 응답 확인
4. 에러 메시지 확인 ("인증이 필요합니다" 등)
5. 데이터 변경 확인: 신고 상태 미변경, 이메일 미발송

**예상 결과**:

- ✅ 모든 `/api/admin/*` 엔드포인트에서 401 반환
- ✅ 데이터 변경 작업 모두 차단
- ✅ 오류 메시지 명확함

### 시나리오 12: XSS 방지 (입력 이스케이핑)

**목표**: HTML 태그 및 스크립트 인젝션 방지

**단계**:

1. 신고 관리에서 신고 내용에 HTML 태그 포함된 신고 생성:
   ```
   신고 내용: "<script>alert('XSS')</script> 문제 있습니다"
   ```
2. `/admin/reports`에서 신고 목록 조회
3. 신고 상세 Dialog 열기
4. 신고 내용이 **이스케이프 렌더링** 확인 (태그가 문자열로 표시됨)
5. 브라우저 콘솔에서 스크립트 실행 안 됨 확인

6. 이메일 발송 Dialog에서:
   ```
   수신자: "attacker@example.com\nBcc: victim@example.com"
   제목: "헤더 인젝션 테스트<br>분기됨"
   ```
7. "발송" 클릭
8. 이메일 발송 API 호출 실패 (유효성 검증) 또는 발송된 메일에서:
   - 개행이 문자열로 처리됨 (헤더 인젝션 차단)
   - HTML 태그가 이스케이프 렌더링됨

**예상 결과**:

- ✅ HTML 태그 이스케이프 처리
- ✅ 스크립트 태그 렌더링 안 됨
- ✅ 개행 문자 유효성 검증 (개행 인젝션 차단)
- ✅ 이메일 헤더 인젝션 방지

### 시나리오 13: 속도 제한 (Rate Limiting)

**목표**: 이메일 발송 분당 건수 제한 검증

**단계**:

1. 로그인 후 이메일 발송 Dialog 열기
2. **분당 6건 이상** 발송 시도:
   ```javascript
   // 스크립트로 연속 5번 발송 (성공)
   for (let i = 0; i < 5; i++) {
     // API 호출
   }
   // 6번째 발송 시도
   ```
3. 처음 5건: 성공 (201)
4. 6번째 이후: 429 Too Many Requests 응답 확인
5. 에러 메시지 표시 확인 ("분당 5건까지 발송 가능합니다" 등)
6. 60초 대기 후 재시도 → 성공

**예상 결과**:

- ✅ 분당 5건까지는 정상 발송
- ✅ 초과 시 429 응답
- ✅ 사용자 친화적 에러 메시지
- ✅ 시간 경과 후 제한 해제

```env

# 관리자 인증 (v3.0 신규)

# 이메일 발송 (선택)
EMAIL_API_KEY=re_...                              # Resend API 키
EMAIL_FROM_ADDRESS=noreply@example.com

# 애플리케이션
NEXT_PUBLIC_APP_URL=http://localhost:3000
```
